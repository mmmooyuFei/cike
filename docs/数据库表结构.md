# 数据库表结构

> 适用于本项目当前版本，默认运行在 PostgreSQL（生产使用 18，本地开发可用 SQLite）。
> 表在应用启动时由 SQLAlchemy `Base.metadata.create_all()` 自动创建，**新增表不需要手工建表**；
> 给已有表加列没有迁移框架，需要手工 `ALTER TABLE`，改前先备份。

## 连接与通用约定

- 连接串来自服务器 `.env` 的 `DATABASE_URL`，仓库里只有 `.env.example`，不包含真实口令。
- 共 **15 张表**：5 张系统表 + 10 张业务表。
- 业务数据按用户隔离：所有业务表都有 `user_id`，关联 `users.id`，接口查询始终带当前用户条件。
- 软删除：业务表用 `deleted_at` 标记删除，列表查询过滤 `deleted_at IS NULL`；撤销即置回 `NULL`。
- 部分唯一：同日日志 / 睡眠、同月同账户资金、同日打卡的唯一索引都带 `WHERE deleted_at IS NULL`，
  所以删除后可以重建，恢复时若同键已有记录会冲突。
- 时间：`created_at` / `updated_at` 等统一存 **naive UTC**；页面上的“今天/现在”按
  `APP_TIMEZONE`（默认 `Asia/Shanghai`）计算，不依赖容器 `TZ`。
- 类型映射：`String(n)` → `VARCHAR(n)`、`Text` → `TEXT`、`Integer` → `INTEGER`、
  `Boolean` → `BOOLEAN`、`Date` → `DATE`、`DateTime` → `TIMESTAMP WITHOUT TIME ZONE`、
  `JSON` → `JSON`、`Numeric(14,2)` → `NUMERIC(14,2)`、`Float` → `FLOAT`。
- 时间点（睡觉/起床/专注开始）用 `VARCHAR(5)` 存 `"HH:MM"`，与日期分开。

## 表清单

| 表 | 中文 | 用途 |
|---|---|---|
| `users` | 用户 | 登录身份与应用内资料、角色、管理员标记 |

| `oidc_states` | OIDC 临时状态 | 授权码流程的 state / PKCE / nonce |
| `app_settings` | 站点设置 | 品牌名称、副标题、LOGO 地址 |
| `access_rules` | 模块访问规则 | 按角色/群组/用户限制模块可见与可编辑 |

| `habits` | 坚持事项 | 每天/每周/每月的坚持目标 |
| `habit_logs` | 打卡记录 | 每个事项每天一条打卡 |
| `milestones` | 年度里程碑 | 目标、衡量标准、进度、复盘 |
| `daily_logs` | 每日日志 | 今日内容、明日计划、卡点 |
| `sleep_records` | 睡眠 | 睡前/起床时间、目标、达标、时长 |
| `focus_sessions` | 专注学习 | 一段专注/学习记录与收获 |
| `workouts` | 健身 | 项目、时长、强度、消耗 |
| `money_records` | 月度资金 | 每月每账户期初/期末/净变动 |
| `weekly_reviews` | 周回顾 | 每周三个问题的回顾 |

关系：`users 1—N` 所有带 `user_id` 的表；`habits 1—N habit_logs`；`sessions` 属于用户；
`access_rules`、`app_settings`、`oidc_states` 独立（不按用户隔离）。

## 常用查询

```sql
-- 某用户未完成的待办（按截止日期、优先级）
SELECT id, title, priority, due_date
FROM todos
WHERE user_id = :uid AND deleted_at IS NULL AND status <> 'done'
ORDER BY due_date NULLS LAST, priority;

-- 某用户本月各坚持事项打卡数
SELECT h.id, h.title, h.frequency, h.target_count,
       count(l.id) FILTER (WHERE l.log_date >= date_trunc('month', current_date)::date) AS month_done
FROM habits h
LEFT JOIN habit_logs l
       ON l.habit_id = h.id AND l.deleted_at IS NULL
WHERE h.user_id = :uid AND h.deleted_at IS NULL AND h.status = '进行中'
GROUP BY h.id, h.title, h.frequency, h.target_count
ORDER BY h.created_at;

-- 个人总余额：各账户最新月份的期末加总
SELECT sum(closing)
FROM (
  SELECT DISTINCT ON (account) closing
  FROM money_records
  WHERE user_id = :uid AND deleted_at IS NULL
  ORDER BY account, month DESC
) latest;

-- 最近 7 天专注时长
SELECT session_date, sum(minutes)
FROM focus_sessions
WHERE user_id = :uid AND deleted_at IS NULL
  AND session_date >= current_date - 6
GROUP BY session_date
ORDER BY session_date;

-- 撤销一条软删除记录
UPDATE todos SET deleted_at = NULL
WHERE id = :id AND user_id = :uid AND deleted_at IS NOT NULL;
```

> 恢复日志/睡眠/资金/打卡前先确认同键没有未删除记录，否则会撞部分唯一索引。

## 变更注意

1. **新增表**：在 `backend/app/models.py` 里加模型即可，容器启动时自动创建。
2. **修改已有表**：没有迁移框架，需要手工 `ALTER TABLE`；上线前先 `pg_dump` 备份。
3. **不要直接改 `deleted_at` 做“硬删除”**：业务接口依赖它做撤销与唯一性判断。
4. 新增业务表请带上 `user_id`、`created_at/updated_at`、`deleted_at`，并在列表查询里过滤软删除。
5. 会话表里的 `idp_*_token` 是加密文本，不要当明文读写，也不要导出到日志。
